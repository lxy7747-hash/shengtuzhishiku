# 真实在线生图与多引擎适配工作流

## 1. 背景与核心价值

在传统生图流程中，创作者通常需要在多个平台间来回跳转：在拼装台生成提示词 -> 复制到剪贴板 -> 打开 Midjourney / WebUI / 硅基流动 -> 手工填写负面词与 `--ar` 参数 -> 等待出图 -> 回头修改提示词。这种断裂的体验导致试错迭代成本高，且容易在复制过程中丢失负面约束或参数格式。

本工作流通过在 [[PromptStudio AI]] 中引入**在线生图代理**与**多引擎参数格式适配器**，形成从“配方拼装/视觉反推 -> 格式转化 -> 一键在线出图 -> 即时成图预览与下载”的完整闭环。

## 3. 多引擎参数适配逻辑

### 3.1 中文 / GPT Image (DALL-E 3)
- **特点**：擅长自然语言长文本与连贯空间逻辑叙述。
- **处理方式**：保留分层结构与自然语言流畅段落，在末尾附带画幅尺寸约束，无须机械去除标点。

### 3.2 Midjourney v6.1
- **特点**：对 Markdown 标记、特殊字符敏感，依赖尾缀 Flags 控制出图参数。
- **处理方式**：
  1. 剥离 Markdown 标题（`#`）与中括号（`【...】`）。
  2. 提取全局负面约束，转化为 `--no ...` 参数。
  3. 自动注入黄金参数尾缀：`--ar {selectedAr} --v 6.1 --style raw --c 5 --q 2`。

### 3.3 Flux.1 / Stable Diffusion
- **特点**：主流开源模型需要严格区分**正向提示词 (Positive)** 与 **负面约束词 (Negative)**。
- **处理方式**：
  1. 正词区：保留服饰、面料受力、光影构图与模特 DNA。
  2. 负词区：提取拉腿、粗跟、防水台、三摄模组、假面塑料皮、影楼死光等否定词。
  3. 提供一键分步复制（正词 / 负词）或整体结构化复制。

## 4. 在线生图代理实现架构

为保护用户的 API Key 安全，并在浏览器端避免 CORS 跨域问题，系统采用 Next.js 服务端路由代理架构：

```
[前端 Web (PromptStudio / ObjectiveLab)]
               │ (POST /api/generate-image)
               ▼
[本地 Next.js 服务端代理 (src/app/api/generate-image/route.ts)]
               │
      ┌────────┴────────┐
      ▼                 ▼
[SiliconFlow FLUX]   [OpenAI DALL-E 3]
  (国内极速 FLUX.1)      (官方 DALL-E 3)
```

- **统一参数映射**：
  - OpenAI 接口使用 `size: "1024x1792"`。
  - SiliconFlow 接口使用 `image_size: "720x1280"` 与 `batch_size: 1`。
- **降级与容错**：自动识别 Base URL 路由；若返回 Base64，自动封装为 `data:image/png;base64,...`；遇到超时提供长达 120 秒连接缓冲。
