# LLM 维护持久 Wiki / 第二大脑模式

## 来源说明

该文件来自用户在 2026-06-21 提供的一段想法文本，描述一种不同于传统 RAG 的知识管理模式：LLM 不是每次查询时从原始文档重新检索和拼接答案，而是持续构建并维护一个持久、结构化、互联的 Markdown Wiki。

## 原文整理

多数人与 LLM 和文档交互的体验类似 RAG：上传文件集合，LLM 在查询时检索相关 chunk 并生成答案。这可用，但每次问题都在从头重新发现知识，缺少积累。

这个想法不同：LLM 不是只在查询时检索 raw documents，而是逐步构建和维护一个持久 wiki。新来源加入时，LLM 读取、提取关键信息，并整合进现有 wiki：更新实体页、修订主题摘要、记录新数据与旧说法的矛盾、强化或挑战演化中的综合。

关键区别：wiki 是持久、复利的 artifact。交叉引用已经存在，矛盾已经被标记，综合已经反映读过的内容。每增加一个来源、每提出一个问题，wiki 都变得更丰富。

用户很少亲自写 wiki；LLM 负责总结、交叉引用、归档和维护。用户负责 sourcing、探索和提出好问题。Obsidian 是 IDE；LLM 是程序员；wiki 是代码库。

## 适用场景

个人目标、健康、心理、自我提升；长期研究；读书 companion wiki；团队内部 wiki；竞品分析、尽调、旅行规划、课程笔记和兴趣深潜。

## 架构

三层：Raw sources（不可变事实来源）、Wiki（LLM 生成和维护的 Markdown 知识层）、Schema（例如 AGENTS.md，规定结构、约定和工作流）。

## 操作

- Ingest：处理新来源，写摘要，更新 index、实体/概念页、综合页和 log。
- Query：基于 wiki 回答，并把有价值答案沉淀回 wiki。
- Lint：周期性健康检查矛盾、过时说法、孤立页、缺失概念、缺失链接和数据空白。

## 索引与日志

`index.md` 是内容目录；`log.md` 是 append-only 时间线。

## 可选工具与技巧

可选地使用本地 Markdown 搜索工具，例如来源提到的 `qmd`。Obsidian Web Clipper、下载图片到本地、图谱视图、Marp、Dataview、Git 都可辅助该模式。

## 为什么有效

知识库难点是维护负担：交叉引用、更新摘要、记录矛盾、保持一致。LLM 能低成本反复执行这些 bookkeeping；人类负责策展、提问和判断。

该想法与 Vannevar Bush 的 Memex 精神相近：私人、主动策展、重视文档间关联。LLM 补上了维护者这一缺口。
